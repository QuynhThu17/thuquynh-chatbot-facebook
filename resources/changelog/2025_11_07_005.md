# Changelog 2025-11-07-005

## Thay đổi: API GET /api/v1/crm/histories và GET /api/v1/crm/customers/{customer_id}

### 1. API GET /api/v1/crm/histories
Thêm field `customer_info` đầy đủ vào response để cung cấp toàn bộ thông tin chi tiết về khách hàng.

**Customer_info bao gồm tất cả các trường:**
- `_id`: ID document của customer (dùng cho API GET /api/v1/crm/customers/{customer_id})
- `customer_id`: ID từ social platform (Facebook sender ID)
- `name`, `phone`, `email`, `address`, `gender`
- `status`, `tags`, `auto_reply`
- `additional_info`: Thông tin bổ sung
- `social_id`, `social_page_id`, `user_id`
- `created_at`, `updated_at`

### 2. API GET /api/v1/crm/customers/{customer_id}
Sửa API để có thể tìm customer theo **cả 2 cách** (chỉ cần match 1 trong 2):
- Theo `_id` (document ID): `/api/v1/crm/customers/67321abc...`
- Theo `customer_id` (social platform ID): `/api/v1/crm/customers/684930451376580`

### Lý do thay đổi
- Cần đầy đủ thông tin customer trong histories để hiển thị thông tin khách hàng
- API GET customer cần linh hoạt tìm theo cả `_id` và `customer_id` để dễ sử dụng từ nhiều context khác nhau
- FE có thể navigate đến chi tiết khách hàng bằng cả 2 loại ID
