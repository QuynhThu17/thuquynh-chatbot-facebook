# Changelog - 2025-01-06-004

## 🔄 Luôn Gọi Song Song search_products VÀ search_knowledge

### Vấn đề
**Scenario:**
```
User: "túi maggie giá bao nhiêu"
→ Bot classify: product_search
→ Tool selector chỉ chọn: ["search_products"]
→ search_products không tìm thấy → return "❌ Không tìm thấy sản phẩm"
→ ❌ BỎ QUA search_knowledge (có Q&A pairs về giá túi Maggie)
→ Bot trả lời: "Không tìm thấy" (SAI!)
```

**Root cause:** `ToolSelector.select_tools()` với intent `product_search`:
```python
# ❌ CŨ: Chỉ gọi search_products khi không có keywords chính sách
if intent == "product_search":
    if not any(kw in query_lower for kw in ['chính sách', 'quy định']):
        tools = ["search_products"]  # BỎ QUA search_knowledge!
```

→ Khi `search_products` không tìm thấy, bot không có fallback từ Q&A knowledge base!

### Giải pháp

**ToolSelector.select_tools() - LUÔN gọi cả 2 tools song song:**

```python
if intent == "product_search":
    # ✅ LUÔN GỌI CẢ search_products VÀ search_knowledge song song
    # Lý do: search_knowledge chứa Q&A pairs có thể trả lời câu hỏi về sản phẩm
    # VD: "túi Maggie giá bao nhiêu" → search_products có thể không tìm thấy
    #     nhưng Q&A pairs có câu trả lời về giá
    tools = ["search_products", "search_knowledge"]
    
    logger.info(f"🔧 Product search: Will call both search_products AND search_knowledge in parallel")
```

**Benefits:**
1. **Fallback mechanism**: Nếu `search_products` không tìm thấy → vẫn có Q&A từ `search_knowledge`
2. **Better coverage**: Q&A pairs có thể chứa thông tin bổ sung (giá, chính sách, hướng dẫn...)
3. **Parallel execution**: 2 tools chạy đồng thời → không tăng latency
4. **Comprehensive response**: Bot có cả thông tin sản phẩm + Q&A guidance
